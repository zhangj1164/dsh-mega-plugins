# dsh-client-ui-memo

[English](README.md) | 中文

备忘面板的浏览器端 UI 插件：以 memo Host Remote 为后端的四维度（周 / 月 / 季度 / 年）卡片看板，支持 AI 分析、报告导出、日志分析和 Issue 创建。

## 插件

纯 UI 界面插件：主机端 `apply` 为空，仅使插件出现在主机 `cordis.yml` / Loader 中；浏览器端通过 `exports["./client"]` 交付，由 `package.json` 的 `dsh.client` 声明发现。

看板是一等的主面板。`sidebar.panellist` 条目为它提供侧边栏按钮——该按钮本身、其无障碍名称与选中态都由侧边栏掌控，因此本插件只贡献一个 `currentColor` 图标；键控的 `main` 条目在该面板 id 被选中时渲染看板。关闭看板会通过 `ctx.layout` 选中保留的 `conversation` 面板，因为面板选择权属于 layout 服务而非组件内部状态。插件在 `inject` 中声明 `layout`，但不为它增加 npm 依赖：该服务由外壳提供、经上下文访问，与本包对待 `dsh-client-ui-slots` 的方式一致。本插件不注入任何全局 DOM、不监听侧边栏、不自行定位面板。

## 维度与历史

看板提供四个维度，每个维度各自维护历史，切换维度时历史列表随之切换：

| 维度 | 周期标签 | 拉取范围 | 展示标签数 |
|---|---|---|---|
| 周 | `2026-W37` | 最近 400 个 ISO 周 | 每年 ≤ 10 |
| 月 | `2026-09` | 最近 400 个月 | 每年 ≤ 10 |
| 季度 | `2026-Q3` | 最近 400 个季度 | 每年 ≤ 10 |
| 年 | `2026` | 最近 400 年 | ≤ 10 |

每个维度只拉取一次完整时间线——400 是主机自身的上限，即主机愿意给出的全部——标签规则与年份切换都在这份数据上于浏览器端计算。因此无论用户停留在某一年还是跨越所有年份，一个维度的宿主调用都只有一次。

**哪些周期会成为标签。** 只有至少含一条备忘的周期，以及当前周期——当前周期始终在列，否则空的新周就无法添加备忘。按时间倒序，每个维度每年最多 10 个；更早的通过切换年份到达。「是否为空」按卡片判断，而不是看主机的 `weekCount`：主机为当前周创建零条目行，所以 `weekCount` 为正只说明该周**有行**，不说明**有备忘**。

**年份切换。** 位于维度切换右侧，只提供含标签的年份，按时间倒序，且当前年始终在列（即使尚未存储任何内容）。因此每个选项都通向实际存在的内容。切换年份是本地操作：在该年内重新选取一个标签，不产生宿主调用。

历史列表由主机提供（`memo/listPeriods`），而不是在浏览器端重新计算，因此主机用于分析的周期边界与看板展示的边界不会出现偏差。

**周期归属规则。** 一周归属于包含其**周四**的周期（ISO 8601 规则）。因此月与季度都恰好把一年的周切分一次，既不遗漏也不重叠；跨月边界的那一周只归属于一个周期而不是两个。一周可容纳任意数量的卡片，卡片归属其所在周对应的周期，因此同一张卡片可以在多个维度下出现，而在存储中仍是一条记录。

## 控制器方法

| 方法 | 服务 | 行为 |
|---|---|---|
| `refresh(period?)` | memo | 加载周列表与周期时间线，再据此推导所选周期的卡片。 |
| `selectPeriod(period)` | memo | 切换维度并重新加载该维度的历史。 |
| `selectLabel(label)` | — | 选中某个历史周期，将看板收窄到该周期。 |
| `selectYear(year)` | — | 展示另一年的标签，并在该年内重新选中一个标签。 |
| `addCard(content)` | memo | 向所选周期的目标周添加一条文本记录。 |
| `updateCard(card, content)` | memo | 更新卡片；非当前周期会置 `force` 标记。 |
| `duplicateCard(card, suffix)` | memo | 将卡片复制到同一周，并为副本追加后缀。 |
| `deleteCard(card)` | memo | 删除卡片。 |
| `analyze(type)` | memo | 对所选周期运行 AI 分析（梳理 / 总结 / 分析）。 |
| `exportReport()` | memo | 为所选周期导出 Markdown 报告。 |
| `analyzeLogs()` | memo | 读取遥测失败记录并生成带预填 URL 的 GitHub issue 报告。 |
| `optimizeIssue(description)` | githubIssue | 将自然语言描述优化为结构化报告。 |
| `archiveCurrentQuarter()` | memo | 归档看板当前所在的季度。在其他维度下为空操作。 |
| `unarchiveQuarter(label)` | memo | 将某季度移出归档，恢复其卡片可编辑。 |

## 模型路由解析

浏览器端从不选择模型。控制器**不**发送 `provider` 与 `model` 字段，因此路由由主机先从部署配置、再从会话默认值解析；若均未注册则返回精确的失败原因。携带硬编码 provider 名称的请求只可能在恰好注册了该名称的那一个部署上成功。

## UI 功能

- **四个维度页签**（周 / 月 / 季度 / 年），同一行右侧带**年份切换**：每个维度只为「有备忘的周期」与当前周期生成标签，每年最多 10 个，因此空的历史周不会变成标签
- **卡片网格**，采用官方 Agent 预设风格：固定列宽、等高行、固定尺寸卡片
- **卡片操作**：查看（只读详情弹窗）、编辑（编辑弹窗）、复制（复制到同一周期）、删除（确认弹窗）
- **输入区**，带虚线通栏创建按钮，草稿为空时禁用
- **AI 分析**，可切换类型（梳理 / 总结 / 分析），结果以卡片就地展示
- **报告导出**，针对所选周期
- **日志分析**，生成预填 GitHub issue；入口放在头部，因为它的产物是 issue 而非关于备忘的报告
- **Issue 编辑器**：自然语言输入、LLM 优化，并按配置的仓库打开 GitHub
- **复制完整正文**：复制未截断的报告，使为适配 GitHub URL 长度而被缩短的正文仍可粘贴
- **结果卡片**（分析 / 报告 / 日志分析）：每张卡片右上角各带折叠开关与关闭图标。折叠是组件内的展示状态；关闭即清除该结果——结果是视图态而非已存数据。
- **添加 Issue、日志分析、关闭**为看板头部的图标+文字按钮，关闭在最右侧
- **按季度归档**：工具条中的「归档本季度」（仅在季度维度出现——那是季度标签唯一无歧义的地方）。归档后该季度的卡片在**所有**维度下变为只读：编辑、复制、删除三项都被撤下，因为它们都会改动用户已经宣告结束的季度，而查看仍然可用。编辑按钮的位置变为「取消归档」，取消归档会释放整个季度——因为归档的单位就是季度。已归档卡片降对比度、边框改为虚线，并带「已归档」标记。
- **只读在所有可能泄漏的地方都已封闭**：查看弹窗遵循与卡片相同的规则，因此已归档卡片的「查看」会在「编辑」应在的位置显示「取消归档」，而不是把编辑放回那个被撤下的按钮旁边。当新卡片将落入的周已归档时，输入区被禁用、说明原因，并就地提供取消归档动作。控制器同样会拒绝该写入，因此弹窗打开期间才落地的归档也无法漏过；宿主则另行以 `quarter-archived` 拒绝。

## Bundle 层

该包包含在 `dsh-memo` bundle 的 `cordis.patch.yml` 中，作为 `ui-memo` 行。无需单独 bundle。

## 测试

`tests/logic.spec.ts` 覆盖纯粹的周期、标签与年份逻辑；`tests/controller.spec.ts` 以假 Remote 驱动控制器；`tests/MemoBoard.spec.tsx` 在 jsdom 中渲染看板并覆盖全部交互功能，包括头部按钮顺序、标签规则与年份切换、每张卡片的操作、每张结果卡片的折叠与关闭、分析与导出操作，以及"任何请求都不得携带模型路由"这一回归；`tests/entry.spec.tsx` 以替代的客户端上下文执行真实浏览器端入口，因此两个槽位注册、侧边栏图标、关闭时的面板切换、语言词典、样式销毁以及面板组件本身都在外壳真正触达的位置得到覆盖。

## 已知限制

- **仅文本录入** — 当前 UI 支持文本条目；图片和文件附件类型在后端已有定义，但尚未接入 UI。
